Experimental design

Question: what does a CBT-protocol agent do differently from a bare-minimum assistant when both face the same 10 complicated, emotionally-loaded situations?

Agents: two system prompts, frozen before the study. Baseline Helper gets one sentence ("You are a helpful assistant. Reply to the user's message. Do your best with whatever they send."). CBT Agent gets a 9-step CBT protocol it applies to every task, whatever the task is: separate situation from thought, name emotions, surface the hot thought, label distortions, weigh evidence for and against, construct a balanced thought, prescribe a behavioral experiment, still deliver the concrete artifact, and end with a Socratic question. CBT is the processing method, not a persona.

Tasks: two sets. Set A — 10 emotionally-loaded situations (job-loss spiral, filtered review, silent friend, interview eve, 3am health anxiety, quiet husband, thesis freeze, LinkedIn comparison, bedtime guilt, imposter assignment), each with planted distortions and a concrete deliverable. Set B — 6 debugging tasks sharing ONE symptom family (an integration test red in CI, green locally, looking intermittent) and one cognitive-error family (premature certainty: an interpretation treated as a fact), with six different root causes — timezone, shared state, unawaited task, config precedence, mock leakage, hash order — and, in each, an attractive trap fix that turns CI green without fixing anything (the debugging analog of a CBT safety behavior). Every Set B root cause, trap, and fix is machine-verified by an executable repro (tasks/setb_repros/*.py, all exit 0), so C9 scoring is anchored to executed ground truth, not opinion.

Rubric: 10 criteria × 0–2 points, locked in rubric/scoring_sheet.md before a single Set A run existed; the Set B interpretation was locked in rubric/scoring_sheet_setb.md before any Set B run; Set C replaced criterion scores with pre-registered step checklists (rubric/scoring_sheet_setc.md) — expected steps with marks, anti-steps that subtract (some task-failing), and ordering rules, all derived from standard engineering practice rather than either agent's prompt. Two criteria are critical in A/B (C1, C10); a run passes at ≥14/20 with no critical zero. Results append per set — they never overwrite.

Set C (Level 3): five problem-solving tasks designed adversarially so divergence can appear in both directions — ceremony-under-time-pressure (T18), a calm user with no psychological content (T19), a plausible frame the correct answer must escape (T20), a user who is simply right (T21), and exploration foreclosure (T17). Pre-registered predictions were quarantined in results/setc_predictions.json and scored afterwards on the dashboard. Set C found the CBT agent's first failures — matching published findings that rigid full-protocol CBT prompting is the weakest archetype (see RESEARCH.md).

Runs: both agents were played by the same underlying model (the ZCode harness model), strictly under each frozen system prompt — so the system prompt is the only manipulated variable. One sample per condition. (A live OpenAI API attempt returned HTTP 429, so runs were authored in-model rather than via external calls; the transcripts, prompts and scores are all shipped as files for audit.)

Judging: every score carries a quoted evidence snippet so it can be audited. Disclosed limitation: judge and generator share the same underlying model, so treat this as a structured expert review demonstrating the method, not an independent benchmark.
