The mana-elixir mystery actually solves itself once you connect two facts you already found:

1. `populate_cache()` — the only place `mana-elixir` exists — mutates the module-level `CATALOG` dict.
2. CI runs the full suite in file order, where `test_cache_populates` runs before `test_catalog_listing` (alphabetically and as defined).

So in CI, the cache test mutates the shared `CATALOG`, and then the listing test snapshots the *mutated* dict — hence the extra `mana-elixir: 7` key in your diff. When you run `test_catalog_listing` alone, the polluter never runs, and it passes. That's why it looks flaky and isn't: it's 100% deterministic order dependence.

Don't skip the test in CI. The `-k 'not catalog_listing'` route and the `skipif` both just hide the interaction, and the next test that touches `CATALOG` will walk into the same pollution. The proper fix is isolation — give each test a fresh copy of the catalog:

```python
import copy
import pytest

@pytest.fixture
def catalog():
    return copy.deepcopy(CATALOG)

def test_cache_populates(catalog):
    populate_into(catalog)          # mutate the test's own copy
    assert "mana-elixir" in catalog

def test_catalog_listing(catalog):
    assert snapshot_of(catalog) == EXPECTED
```

If refactoring `populate_cache` to write into an explicit target is too invasive this week, the minimal version is a fixture that restores `CATALOG` after each test (`addCleanup`) — but the deepcopy-per-test pattern is the durable answer.

So: no skipif needed, suite green, QA sign-off unblocked, and you've removed a landmine for the next person. This was a good catch on your part — you'd already grepped your way to the answer.
