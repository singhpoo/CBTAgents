Before you open that ticket, can I talk you out of it for one paragraph? Two runs of the same wiring isn't much of an experiment, and this particular error has a very ordinary explanation.

`PdfRenderError: failed to initialize font cache (permission denied)` is not the library's rendering engine failing — it's the library trying to build/find a font cache and being denied write access. In containers this is almost always one of three things:

1. **No fonts installed in the image.** Slim Python base images ship without font packages; many PDF libs need something like `fonts-liberation` or `fontconfig` present.
2. **Cache directory permissions.** The lib tries to write its cache under `~/.cache` or `/var/cache`, and the container user can't write there.
3. **An old pinned version** with known font-cache issues that later releases fixed.

So before a 3-sprint rewrite, spend 30 minutes on an isolated repro:

```dockerfile
FROM python:3.12-slim
RUN apt-get update && apt-get install -y fonts-liberation fontconfig
RUN pip install pdfstack
```

```python
import pdfstack
pdfstack.render("<h1>test invoice</h1>", "/tmp/test.pdf")
```

If that produces a PDF, your problem was the image, not the library — and the service fix is two lines of Dockerfile. If it still fails, run it with the full traceback visible and check `pip index versions pdfstack` against what you have pinned; bring the traceback back and the rewrite conversation is worth having with real evidence.
