**The fix (the real one):** structured concurrency —

```python
async def handle_checkout(order):
    ...
    await sync_invoice(order.id)          # response waits for the write it implies
    return response
```

If the response genuinely must not block on the write, keep the task but make it *owned* — hold it and await it (`await asyncio.gather(*tasks)`) or have the test await the exposed task before asserting. The assert stops being a bet on machine load; it becomes a guarantee.

**Why the trap is a trap:** `sleep(0.5)` (or retries) buys a high pass rate by paying ~0.5s per test forever — and the race window doesn't close, it just narrows: next quarter's bigger deploy window can still lose the same bet three times in a row, at 3am, with no one debugging slowly. It relieves this week's feeling and hands the same bug to a more tired version of you.
