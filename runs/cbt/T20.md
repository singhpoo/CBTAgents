**Distortions at work:** A subtle one — *confirmation by correlation*: the spikes feel like a smoking gun, but co-occurrence isn't mechanism. **Evidence against — and this is where the theory wobbles:** A cache stampede causes duplicate *reads* or duplicate *recomputation*; it doesn't naturally produce two committed *writes* unless the handler itself runs twice — and a handler doesn't run twice because a cache is hot. Meanwhile the retry bump has exactly the right signature for duplicate writes: client times out → retry fires → handler executes twice → two orders, no idempotency key to tell them apart. And note the arrow problem in your correlation: if duplicates doubled order traffic, Redis CPU would spike *because of* the duplicates — the effect pretending to be the cause. So the question that discriminates: when a duplicate pair happened, did the second POST arrive *after a timeout* on the first — and did the cache, or any read path, even participate?
